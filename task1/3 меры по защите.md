# Проверка механизмов защиты данных

## Система тегирования данных

Назначение тегов для конфиденциальных данных с целью обеспечения надлежащей обработки, контроля и автоматизированной защиты.

* PII — персональные сведения
* MED — медицинская информация
* FIN — финансовые сведения
* SEN — данные, требующие аудита и шифрования
* TEM — временные данные, подлежащие удалению

## 1. Процесс регистрации пациентов

| Категория данных                                                    | Методы защиты                                                                                        |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| PII - Личные данные (ФИО, телефон, адрес и прочее)                  | Шифрование, RBAC, маскирование, тегирование, аудит операций                                          |
| MED - Медицинские записи (диагнозы, результаты исследований)        | Шифрование, RBAC, тегирование, ключи API для защищённого обмена, электронная подпись, аудит операций |
| FIN - Финансовые документы (договоры, платежные реквизиты и прочее) | Токенизация, шифрование согласно PCI DSS, сегментация данных, аудит операций                         |
| SEN - Учетные записи сотрудников (логины, пароли)                   | Многофакторная аутентификация (MFA), хеширование паролей                                             |
| TEM - Метаданные (время приема, назначения)                         | Обезличивание данных                                                                                 |

## Инструменты / Защитные меры

* Шифрование файлов: BitLocker, VeraCrypt, EFS
* Шифрование баз данных: TDE, pgcrypto
* Защита передачи данных: TLS 1.3, HTTPS, SFTP
* Управление доступом (RBAC/ABAC): Keycloak, Azure AD
* Аудит доступа: SIEM (ELK, Wazuh), Auditd, Microsoft Sentinel
* Тегирование данных: Microsoft Purview, Apache Atlas, Varonis
* Обезличивание и маскирование: Python scripts, Faker, DataMasker
* Защита API: OAuth 2.0, JWT, Scopes, ограничение скорости запросов (Rate limiting)
* Контроль экспорта данных: DLP-системы (в связи с санкциями рекомендуется рассмотреть Ростелеком Solar Dozor DLP)
* Разделение доступа по ролям: группы Active Directory, группы Keycloak, ограничения на уровне файловых систем
